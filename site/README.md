# POKU Pixel FX 공유 사이트

공개 이펙트 갤러리와 로그인한 사용자의 PNG 작품 공유를 위한 Sites 앱입니다. 라이브러리와 스킬은 [공개 저장소](https://github.com/Stankjedi/poku-pixel-fx)에서 제공합니다.

## 사용 및 게시 조건

- 작품은 기존 라이브러리에서 내보낸 픽셀 이펙트와 스프라이트 시트를 대상으로 합니다. 최대 2048×2048 픽셀, 5 MiB 이하 PNG만 허용합니다.
- ChatGPT에 로그인해야 게시와 본인 작품 삭제가 가능합니다. 게시자는 게시 권한과 법적 책임에 동의해야 합니다. 이 동의 자체가 운영자의 법적 책임을 면제하거나 권리를 검증하지는 않습니다.
- 작은 PNG인지 확인할 수 있지만 사진 축소본이나 유해한 이미지를 완벽하게 감지하거나, 실제 픽셀 아트인지 자동으로 보장할 수는 없습니다. 모든 공개 콘텐츠는 신뢰할 수 있는 것으로 간주하면 안 됩니다.

## 업로드 제한과 운영

서버는 Sites가 제공하는 로그인 사용자 ID의 해시로 D1에 예약을 기록하며, 단일 SQL 예약으로 계정당 10분 동안 5회, 24시간 동안 20회, 동시에 공개된 게시물 50개로 제한합니다. 파일 저장이 실패하거나 본인이 삭제하면 활성 예약을 해제하며 시도 기록은 속도 제한에 계속 반영합니다. DB를 사용할 수 없으면 새 업로드를 거부합니다. 이 정책은 정상 동작 여부를 배포 환경에서 검증해야 합니다.

R2와 D1은 하나의 트랜잭션이 아닙니다. 업로드나 삭제 중 프로세스가 비정상 종료되면 실제 파일과 예약이 불일치하여 계정이 보수적으로 제한될 수 있습니다. 오래된 비활성 시도 기록을 정리하는 자동 정책은 없습니다. 여러 계정을 통한 남용이나 금지 콘텐츠를 원천 차단하지 못합니다. 신고 접수, 운영자 검토 및 권리 침해 대응 절차를 정하기 전까지 공개 갤러리 운영 위험은 남습니다.

## 실행과 배포

`site/` 디렉터리에서 Sites Vinext 환경의 `npm ci`, `npm run db:generate`(스키마를 변경할 때만), Sites 빌드 및 배포 워크플로를 사용합니다. 공개 저장소의 `.openai/hosting.json`에는 실제 프로젝트 ID를 포함하지 않습니다. 배포하려면 각자의 Sites 프로젝트를 연결하고 D1 `DB`, R2 `BUCKET` 바인딩을 준비해야 합니다. Sites는 배포 시 마이그레이션을 적용합니다. SQL 마이그레이션과 메타데이터는 버전 관리하고 이미 적용한 마이그레이션은 변경하지 않습니다. 실제 게시물과 사용자 데이터는 소스 저장소에 포함하지 않습니다.

라이브러리 효과를 수정한 뒤에는 저장소 루트에서 `npm run sync:site`를 실행해야 사이트의 번들과 카탈로그가 갱신됩니다. 이 명령은 공유 게시물의 이미지나 서버 데이터를 수정하지 않습니다. 로컬 미리보기의 D1·R2는 공개 사이트와 별도이며 처음에는 비어 있습니다. 별점과 공유 제한 기능을 사용하려면 `dist/server/wrangler.json`을 빌드한 뒤 `drizzle/`의 미적용 마이그레이션을 순서대로 로컬 D1에 적용해야 합니다. 이미 적용한 마이그레이션은 다시 실행하지 마세요.

인증은 Sites가 전달하는 신뢰된 사용자 헤더에 의존합니다. 다른 호스팅 환경에서는 외부에서 위조한 인증 헤더를 제거하고 인증된 사용자 정보를 안전하게 전달하도록 별도의 인증 연동이 필요합니다.
