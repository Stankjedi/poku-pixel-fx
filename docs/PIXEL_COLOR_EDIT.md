# 픽셀 색 편집 — 정확한 색 교체와 명암·공간 램프

원화의 색 구분을 유지하며 특정 색을 바꾸거나, 작성한 팔레트를 사용해 큰 명암을
배치하는 도구이다. 기존 효과의 원본과 기본 렌더링은 바뀌지 않는다.

## 어떤 도구를 사용할까

| 목적 | API | 색을 고르는 기준 |
| --- | --- | --- |
| 옷·머리·장식의 특정 색만 교체 | `replacePixelColors2D` | 입력 RGB가 교체표와 정확히 일치 |
| 두 색 맞바꾸기, 여러 색 순환 교체 | `createPixelColorReplacer2D` | 모든 항목이 수정 전 RGB를 한 번만 참조 |
| 원화의 부피 명암을 다른 색 계열로 표현 | `mapPixelRamp2D`, `mode: 'value'` | 원화의 Oklab 밝기 |
| 길이 방향의 명암·색 흐름 배치 | `mode: 'linear'` | 시작점에서 끝점 방향으로 투영한 거리 |
| 둥근 밝은 중심·색 변화 배치 | `mode: 'radial'` | 중심에서의 원형 거리 |
| 추출한 색을 명암 순서로 정리 | `sortPixelColorsByLightness2D` | Oklab 밝기, 같은 밝기는 입력 순서 유지 |

기존 `remapPixelPalette2D`의 가까운 색 찾기와 목적이 다르다. 정확한 교체표는
기준에 없는 피부색·금속색을 건드리지 않는다. 명암 램프는 원래 색상보다 밝기를
기준으로 같은 색 계열에 묶고 싶을 때 사용한다. 공간 램프는 사용자가 지정한
좌표를 따르며, 그림의 의미나 실제 입체 구조를 추측하지 않는다.

## 1. 정확한 RGB 교체

```ts
import { createPixelColorReplacer2D } from 'poku-pixel-fx';

const recolor = createPixelColorReplacer2D([
  { from: '#32465d', to: '#57334f' },
  { from: '#7392aa', to: '#b2769d' },
]);
const changed = recolor.replace(source, {
  selection: clothingSelection,
  protectedMask: embroideryProtection,
});
```

교체표의 `from`은 원래 RGB와 완전히 같아야 한다. 유사색 허용 오차는 없으며
알파는 검색에 포함하지 않는다. 따라서 같은 RGB를 가진 알파 1·128·255 픽셀을
같은 RGB로 바꾸면서 각자의 알파를 그대로 유지한다.

`A → B`, `B → A`를 함께 주면 두 색이 맞바뀐다. `A → B`의 결과를 다시
`B → A`에 넣지 않는다. 중복 `from`은 모호한 지시가 되므로 거부한다.
항목이 없는 교체표는 독립 버퍼를 가진 동일한 그림을 반환한다.

## 2. 작성한 팔레트로 명암을 매핑

```ts
import { createPixelRampMapper2D } from 'poku-pixel-fx';

const mapper = createPixelRampMapper2D(
  ['#18243b', '#46566e', '#8c9a9b', '#d0c9ae', '#fff0c9'],
  {
    mode: 'value',
    valueRange: [.12, .9],
    gamma: 1,
    dither: 'none',
  },
);
const changed = mapper.map(source, { selection, protectedMask });
```

`value`는 sRGB 바이트를 그대로 평균하지 않고 선형 RGB에서 Oklab의 `L`을
계산한다. 예를 들어 중성 회색의 sRGB 값 112는 Oklab 밝기가 약 0.546이므로
검정·흰색 두 단계 중 높은 쪽에 대응한다. 이것은 고정한 명암 기준이며, 한
프레임에 밝은 픽셀이 더 생겼다고 다른 픽셀의 기준을 다시 정규화하지 않는다.

순서는 다음과 같다.

1. `t = (L - low) / (high - low)`로 범위를 정한다.
2. `t`를 0~1로 제한한다.
3. `t ** gamma`를 적용한다. `gamma > 1`이면 높은 팔레트 단계가 늦게 나타난다.
4. 작성한 팔레트에서 단계 하나를 고른다.

`valueRange`는 `0 ≤ low < high ≤ 1`, 기본값은 `[0, 1]`이다. `gamma`는
`1/64~64`, 기본값은 1이다. 범위와 감마를 모든 프레임에 고정하면 동일 RGB의
명암 위치도 고정된다. 서로 다른 프레임의 공간 변형이나 셀 위치를 자동으로
추적하는 기능은 아니다.

## 3. 직선·원형 팔레트 램프

```ts
const alongBlade = createPixelRampMapper2D(palette, {
  mode: 'linear', start: [8, 40], end: [91, 12],
});
const roundHighlight = createPixelRampMapper2D(palette, {
  mode: 'radial', start: [36, 28], end: [61, 28],
});
```

좌표 `[0, 0]`은 첫 픽셀의 **중심**이다. 셀의 왼쪽 위 모서리가 아니므로
픽셀 중심에 별도로 0.5를 더하지 않는다. 시작점과 끝점은 정수이며 캔버스
밖에 둘 수 있다. 두 점이 같은 공간 램프는 거부한다.

- `linear`: `dot(cell − start, end − start) / |end − start|²`.
- `radial`: `|cell − start| / |end − start|`.

이 값을 0~1로 제한하고 감마를 적용한다. 직선에서는 시작점의 뒤쪽은 첫 색,
끝점 너머는 마지막 색이다. 원형에서는 중심이 첫 색이고 지정한 반지름 이상은
마지막 색이다. 밝은 중심이 필요하면 밝은 색을 앞에 둔 팔레트를 명시한다.

## 단계 선택과 디더링

N색 램프의 색 위치는 `0, 1/(N−1), …, 1`이다. 기본값 `dither: 'none'`은
가장 가까운 위치의 색을 고르고, 정확히 중간이면 높은 인덱스를 고른다.
단일 색 램프도 허용한다. 팔레트의 반복 색은 작성한 단계의 간격을 표현할 수
있으므로 제거하지 않는다.

`bayer4`·`bayer8`은 해당 위치를 둘러싼 **인접 두 단계**만 섞어 배치한다.
새 중간색을 만들지 않고 알파를 디더링하지 않는다. 첫·마지막 및 정확한 램프
표본 위치는 디더링에서도 해당 색을 유지한다. 고정된 네이티브 좌표 패턴이므로
프레임마다 난수를 뿌리는 방식이 아니다.

`origin: [x, y]`는 Bayer 패턴의 위상에만 영향을 준다. 직선·원형 램프의 위치는
바꾸지 않는다. 전체 그림에서 `(cropX, cropY)`에 있는 조각을 독립적으로 같은
결과로 처리하려면 `start`와 `end`에서 잘라낸 위치를 빼고, `origin`에는 그 위치를
더한다. 색조 기반 `value` 모드는 공간 끝점을 사용하지 않으므로 패턴 원점만
더하면 된다. 스프라이트의 월드 배치 `x/y`는 이 작성 좌표와 무관하다.

픽셀 군집을 뚜렷하게 유지하려면 디더링을 끈 상태부터 살핀다. 디더링은 제한된
색 수로 중간 단계를 표현할 때 선택하는 수단이며, 재질 디테일이나 수작업 군집을
자동으로 개선하는 품질 판정이 아니다.

## 팔레트 순서

램프는 **사용자가 지정한 순서**를 그대로 사용한다. 일반적인 명암 매핑과
한 단계 밝게/어둡게 붓에는 어두움→밝음 순서의 램프가 적합하다. 명시적으로
반전한 램프나 반복색 간격도 유효하므로 매핑 중 자동 정렬하지 않는다.

사진에서 추출한 색, 잠금색이 앞에 붙은 팔레트처럼 순서가 명암을 뜻하지 않는
입력은 `sortPixelColorsByLightness2D(palette)`로 복사 정렬한 뒤 램프로 채택할 수
있다. 이 함수는 색 값과 반복 항목을 보존한다. 색 계열이 여러 개인 팔레트 전체를
하나의 명암 램프로 사용하면 다른 재질의 색으로 넘어갈 수 있으므로, 피부·옷·금속
등에는 적절한 영역과 별도 램프를 사용한다.

## 보존·검증·작업량

- 원본 픽셀과 마스크를 수정하지 않고 독립 복사본을 반환한다.
- 미선택·보호·실루엣 밖·알파 0 픽셀의 **숨은 RGB까지** 그대로 보존한다.
- 선택된 셀도 알파와 독립 실루엣 값은 바뀌지 않는다.
- 높이·법선·재질 ID·HDR·소켓 등 부가 데이터는 같은 참조를 유지하며 수정하지 않는다.
- 교체표·팔레트·설정은 컴파일 때 복사하고 동결한다. 설정의 JSON 직렬화 후
  재컴파일도 같은 출력 계약을 따른다.
- 최대 16,777,216셀, 4,096개 정확한 교체 항목, 256색 램프를 받는다.
  좌표와 디더 원점은 정수 ±1,048,576 범위이다.
- 명암 계산 캐시는 최대 8,192개 RGB로 제한한다. 색이 더 많아도 나머지를
  생략하거나 근사하지 않고 직접 계산한다. 처리량은 셀 수에 비례한다.
