# Pixel Art Production — 색 설계와 애니메이션 재편집

이 확장은 이미 작성한 실루엣·소재 결·높이를 유지하면서 색을 정확하게 다듬고,
시트로 전달받은 애니메이션을 다시 편집하는 흐름을 연결한다.
기존 FX 원화와 기본 렌더링은 변경하지 않는다.

## 실행

```sh
npm ci
npm run build
npm run gallery
```

`http://127.0.0.1:8080/gallery/pixel-art-lab.html`에서 **정확한 색 교체 · 팔레트 명암**을 연다.
애니메이션 영역에는 **스프라이트시트를 편집 가능한 프레임으로 가져오기**가 있다.

## 1. 필요한 색만 교체

1. 색 추출 도구로 원화의 색을 고른 뒤 **추출한 색 사용**을 누르거나 원래 색을 직접 지정한다.
2. 새 색을 고르고 **정확히 일치하는 색 교체**를 누른다.
3. **두 색 맞교환**을 켜면 A→B와 B→A가 같은 원본을 기준으로 한 번에 실행된다.
4. **선택 내부만**은 선택과 보호 영역을 함께 지킨다. 보호 영역이 우선한다.
5. **모든 애니메이션 프레임에 적용**은 각 프레임의 선택·보호를 사용한다.

색 비교는 RGB가 완전히 같은지 확인한다. 알파 1·128·255인 같은 RGB는 같은 새 RGB를 받으면서
각자의 알파는 유지한다. 알파 0의 숨은 RGB, 독립 마스크로 가려진 셀, 선택 밖, 보호 셀은 그대로다.
두 색을 순서대로 덮어써서 한 색으로 합쳐지는 교환 오류가 없다.

결과는 새 희소 그림 레이어에 저장한다. 원본·기존 레이어·표면 맵은 남고,
새 레이어의 표시/삭제/실행 취소로 원래 상태를 되찾을 수 있다. 모든 프레임 작업도
하나의 애니메이션 기록으로 저장한다. 한 프레임이라도 용량 검증에 실패하면 일부만 적용하지 않는다.

## 2. 팔레트로 명암 설계

작업실 아래에서 팔레트를 추출하거나 그림자·중간색·하이라이트로 명암 팔레트를 만든다.
색 입력칸의 순서는 의미가 있으며 자동으로 바뀌지 않는다. 추출한 팔레트를 처음 작업 팔레트로
채택할 때는 지각 명도순으로 정렬한다. 고정한 색의 RGB는 유지하며 위치만 옮긴다.
따라서 흰색을 고정한 채 추출해도 “한 단계 밝게”가 흰색을 검게 바꾸지 않는다.
임의 순서가 필요하면 색을 직접 편집하고 **팔레트 순서 반전**을 사용할 수 있다.

| 기준 | 사용하는 정보 | 용도 |
| --- | --- | --- |
| 원화의 명도 | sRGB를 선형화한 뒤 계산한 Oklab L | 주름·음영을 유지한 색조 변형, 정해진 명암 램프로 통일 |
| 선형 | 시작→끝 방향으로의 네이티브 픽셀 중심 투영 | 검날의 방향성 명암, 띠나 가장자리의 단계형 색 변화 |
| 방사형 | 시작점에서의 거리 / 시작→끝 거리 | 보석·구체·발광 중심의 원형 명암 설계 |

좌표 `(0,0)`은 첫 번째 픽셀의 중심이다. 끝점은 마지막 색이 되는 위치이며 방사형에서는
반지름을 정한다. 시작점과 끝점이 같은 공간 명암은 적용하지 않는다.
원화 명도 모드는 어두운 끝/밝은 끝으로 입력 범위를 정한다.
**분포**는 정규화한 값을 `t^gamma`로 조절하며 1이 기본이다.

디더링을 끄면 가장 가까운 팔레트 단계를 사용한다. 4×4/8×8 디더링은 서로 이웃한 두
팔레트 항목만 사용하며 물체 좌표에 고정된다. 새 중간색·알파 디더링·프레임별 노이즈를 만들지 않는다.
공간 그라데이션은 색을 위치로 다시 정하므로, 원래 소재 명암을 유지하려면 **원화의 명도** 모드나
명시적 선택 영역을 사용한다. 얼굴·자수·장식은 보호 영역으로 남길 수 있다.

## 3. 작업 팔레트 저장

v2 문서의 선택 필드 `workingPalette`는 1~256개의 packed ABGR 색을 순서대로 저장한다.
부분 알파와 알파 0의 숨은 RGB도 보존하며, signed 입력은 같은 비트 패턴의 unsigned 값으로 정규화한다.
이미지에 적용한 팔레트 레이어와 별개의 작성 정보다. 새 필드가 없는 기존 v1/v2 문서는 그대로 열린다.
v2 프로젝트를 열면 저장된 작업 팔레트를 복원하고, 필드가 없으면 이전 프로젝트의 임시 팔레트를 지운다.
v3의 각 프레임은 자체 팔레트가 우선이며, 없으면 최상위 `workingPalette`를 표시용 기본값으로 사용한다.
기본값을 보는 것만으로 해당 cel의 팔레트 필드나 실행 취소 기록을 만들지 않는다.
빈 프레임을 추가하면 현재 프레임이 직접 저장한 팔레트를 독립된 배열로 복사한다.
프레임을 복제하거나 이미지를 병합해도 팔레트가 남는다.

팔레트 입력 자체는 그림을 변경하지 않는다. 그림에 반영할 때 색 교체·명암 매핑·팔레트 레이어를 적용한다.
작업 팔레트의 입력값은 저장 시 포함되며, 색상 적용 레이어와 함께 기록된 팔레트는 실행 취소에도 따라간다.

## 4. 스프라이트시트 다시 열기

### POKU PNG + 시간 JSON

**POKU 시간 JSON 사용**을 고르고 PNG와 함께 내보낸 `*-sheet.json`을 지정한다.
프레임 사각형·고유 ID·이름·개별 길이·정방향/역방향/왕복·반복 여부를 복원한다.
이미지 크기와 시간 메타데이터가 맞지 않으면 기존 작업을 유지하고 오류를 표시한다.
JSON의 `image` 문자열은 네트워크 요청으로 해석하지 않는다.

### 다른 도구의 격자 시트

**격자 크기로 분할**에서 프레임 크기, 좌우/상하 바깥 여백, 가로/세로 간격과 행/열 우선 순서를 지정한다.
시작 칸은 0부터, 칸 수 0은 마지막 완전한 칸까지다. 가장자리에 남는 불완전한 띠는 프레임으로 만들지 않는다.
빈 셀은 기본적으로 유지한다. **빈 프레임 제외**는 숨은 RGB가 있는 투명 프레임도 버리므로
의도한 공백 재생 시간을 유지하려면 끈 상태로 가져온다.

가져온 프레임은 서로 독립적이며, 곧바로 그리기·선택·재질·색 편집을 할 수 있다.
가져오기도 하나의 실행 취소 단계다. 파일을 읽는 동안 새로 그린 획이나 선택이 생기면
오래된 가져오기 결과를 적용하지 않고 현재 작업을 유지한다.
일반 PNG·프로젝트·스프라이트시트는 하나의 가져오기 잠금을 공유한다. 한 파일을 읽는 동안
다른 입력이 뒤늦게 타임라인을 덮거나 실행 취소 기록을 지우지 않도록 다음 가져오기를 막는다.
일반 PNG와 프로젝트를 여는 중에 계속 그린 경우에도 새 작업을 우선해 오래된 입력을 거부한다.

PNG 시트는 베이크된 색이다. 원래의 레이어나 PNG에 들어 있지 않은 높이를 복구하지 않는다.
원래 작성 구조를 유지하려면 `.poku-pixel-art.json` 프로젝트를 사용한다.
API에 별도의 표면 채널을 전달하면 색과 같은 사각형으로 정확히 잘라 복사한다.

## 5. PNG와 입력 크기

8비트 RGB/gray-alpha/RGBA 및 1/2/4/8비트 indexed/grayscale PNG는 비인터레이스와 Adam7 모두
원본 샘플을 직접 읽는다. 색상 프로파일에 의한 변환은 수행하지 않고 발견한 정보를 안내한다.
16비트 PNG는 정밀 시트 가져오기에서 거부한다. 단일 원화 입력의 기존 명시적 브라우저 변환 경로는 유지한다.

| 경로 | 한도 |
| --- | --- |
| 기존 단일 PNG 입력 | 축별 512픽셀, 262,144셀, 파일 16 MiB |
| 시트 PNG 입력 | 축별 16,384픽셀, 전체 16,777,216셀, 파일 64 MiB |
| 편집 프레임 | 브라우저 축별 4,096픽셀과 기존 문서 1,048,576셀 한도 동시 적용 |
| 애니메이션 | 최대 256프레임, 전체 8,388,608 네이티브 셀, 기존 저장/렌더 예산 |
| 프로젝트 | 직렬화된 JSON 최대 64 MiB |

픽셀 수, 압축 해제 후 정확한 바이트 수, 프레임 합계와 JSON 예산을 검증하고 큰 배열을 만든다.
화면 배율은 네이티브 해상도를 늘리지 않는다.

## 검증과 출력 예제

```sh
npm run test:pixel-art
GPU_BROWSER_PATH=/path/to/chromium npm run test:browser:pixel-production
npm run preview:pixel-production
```

단위 검사는 색 교환·픽셀 중심 좌표·팔레트 경계·투명도·선택/보호·표면 채널·저장 형식과
시트 예산을 검사한다. 외부 인코더로 만든 Adam7 파일과 독립 RGBA 기준값도 비교한다.
실제 브라우저 검사는 버튼·파일 입력·네이티브 포인터 작업·저장/재열기·일괄 실행 취소를 연결해 검사한다.

[네이티브 출력 비교](previews/pixel-art-production/README.md)와
[색 편집 API](PIXEL_COLOR_EDIT.md), [시트 API](PIXEL_ART_SHEET_IMPORT.md)를 함께 볼 수 있다.
출력 비교는 도구의 색·형태 보존을 확인하는 자료이며 미술적 완성도의 자동 인증은 아니다.
