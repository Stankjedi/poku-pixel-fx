# 0.5 제작 품질·GPU·애니메이션 개선 보고서

검토 기준: 2026-11-06, `7fc01f7`의 0.4 메인에서 출발한 코드 감사와 구현.

## 이번 변경의 목적

0.4에는 이미 Studio, WebGPU HDR 후처리, DrawIR, GPU 장식 입자, Rust/wgpu 참조 플레이어,
CharacterAsset, 팔레트 정책과 게임 자산 내보내기가 있었다. 이번 변경은 이 기능을 다시 만드는
대신 실제 제작 경로의 병목과 연결 결함을 고치고, 조합 제작과 픽셀 표현을 확장한다.

"처음부터 완벽한 효과"를 자동 판정하는 기능은 아니다. 좋은 첫 결과를 만들기 위해 필요한
시간 조정, 효과 조합, 장비 동기화, 색상 스타일, 확인 가능한 GPU 경로를 실제 UI와 저장 파일에
연결했다. 결정성·출력 일치·자원 관리의 자동 검증과 작품의 읽힘·미술적 판단을 구별한다.

## 1. 여러 효과를 하나의 기술로 제작

Studio에서 레시피 또는 캐릭터를 열고 **현재 효과로 시퀀스 제작**을 누른다.
라이브러리의 **+ 시퀀스에 추가**로 효과를 더하고 cue별 시작 시간, 표시 시간,
위치, 회전, 반전, 나타남/사라짐, 표시 여부와 순서를 조절한다.
저장·열기·undo/redo·CLI 출력은 같은 프로젝트를 사용한다.

시퀀스의 특징:

- cue ID와 부모 seed에서 안정적인 seed를 유도한다. 목록을 재정렬해도 같은 cue의 입자 모양이 바뀌지 않는다.
- 위치·반전·회전을 반영해 기본 canvas를 자동으로 계산한다. 원하는 canvas와 pivot도 명시할 수 있다.
- 소켓·접촉·사건 이름에 cue ID를 붙이고 시퀀스 시간으로 변환한다.
- 짧은 효과와 반복 효과의 표시 창을 명시할 수 있다. 종료·반복·fade 경계를 동일하게 취급한다.
- 기존 렌더링의 back/front 분리는 유지한다. 목록 순서는 같은 back/front 층 안의 겹침 순서다.

ACT 전체 장면을 자동 변환하지 않는다. ACT의 배우 연기와 hit-stop은 이펙트 자체의 시간과 다르기
때문에 해당 자동 변환 버튼을 비활성화했다. 카탈로그 cue는 효과 그림을 실행하며,
ACT 장면의 배우·대상·presentation freeze까지 자동 복제하지 않는다.
같은 이유로 프레임 좌표의 수동 픽셀 수정, 함께 그리는 배우, 원본 수명 이후의 마지막 프레임
홀드가 있으면 이유를 표시하고 자동 변환을 막는다. 지원되는 변환은 원본 seed·동작 길이·반복,
레이어 표시·여백·카메라·전체 변환과 출력 설정을 유지한다. 합성 cue의 끝은 exclusive이므로
비반복 캐릭터의 마지막 포즈를 길게 유지하려면 별도 표시 구간을 설계해야 한다.

```sh
npm run render -- --project examples/projects/charged-impact.poku-project.json --bundle --trim --deduplicate --padding 2 --extrude 1
```

스키마·이벤트·배치 예제는 [SEQUENCES.md](SEQUENCES.md)를 참고한다.

## 2. GPU 도형 렌더링의 실제 개선 범위

직접 경로는 대략 `픽셀 수 × 도형 수`만큼 후보를 확인한다. 타일 경로는
`타일 수 × 도형 수`의 분류와 `픽셀 수 × 해당 타일 후보 수`의 검사로 나눈다.
국소적인 작은 도형이 넓게 분포할수록 후보를 많이 줄일 수 있다.

각 타일은 최대 256개 후보를 원래 명령 순서대로 저장한다. 한도를 넘으면 그 타일에서 원래의
전체 검사 경로를 사용한다. 밀집 장면에서 정확도를 희생해 도형을 버리지 않는다.
타일 방식은 기존 투명도·깊이·발광 계약을 변경하지 않는다.

GPU Lab에서는 다음을 실제로 확인할 수 있다.

1. 분산/궤도/밀집 장면과 32–4,096개의 추가 도형.
2. `auto`, `tiled`, `none` 경로 선택과 동일 프레임의 결과 비교.
3. GPU 장식 입자 방출과 native pixel PNG 저장.
4. 실제 후보 수·overflow 타일 수의 명시적 진단.
5. DrawIR JSON 저장/열기와 WebGPU 미지원 시 worker CPU 참조 화면.

평상시 프레임은 GPU 결과를 CPU로 읽지 않는다. 비교·진단·PNG 저장을 요청할 때만 readback한다.
후보 검사 횟수 감소와 GPU 프레임 시간은 다른 지표다. 소프트웨어 어댑터 결과로 RTX 등의
물리 장치 성능 향상률을 주장하지 않는다.

기존 카탈로그의 TypeScript Painter와 물리 시뮬레이션이 모두 GPU로 이식된 것은 아니다.
Studio WebGPU는 기존 frame의 HDR 마무리를 담당하고, GPU Lab/DrawIR와 GPU particles는
직접 GPU 도형 경로를 실행한다. Rust/wgpu는 공통 셰이더를 쓰는 참조 플레이어이며
완성된 게임 엔진 플러그인이나 창·입력·월드 시스템은 아니다.

자세한 계약: [GPU_RENDERING.md](GPU_RENDERING.md).

## 3. 캐릭터·장비·애니메이션

장비의 `animations[캐릭터클립]`에서 `time`, `phase`, `source-frame`을 선택한다.
`phase`는 몸체의 전체 동작 주기에 장비 태그 한 주기를 맞춘다. `source-frame`은
가변 프레임 시간과 reverse/pingpong을 포함한 원본 셀 번호를 정확히 따른다.
`source-frame`은 몸체와 장비의 원본 프레임 수가 맞을 때만 제공한다.

장비 색상, 발광, item socket이 같은 원화를 사용한다. 태그를 바꾸기 위해 디코드한 모든
픽셀 배열을 다시 복제하지 않으며, 기존 독립 시간 재생은 기본 동작으로 남는다.

포즈·얼굴 키의 채널 유지와 로컬 반복 시간 수정은 사용자가 일부 관절 또는 얼굴 값만
수정할 때 관계없는 값이 갑자기 바뀌는 문제를 줄인다. 마지막 포즈가 더 넓어지는
비반복 클립도 마지막 프레임까지 bounds에 반영한다.

사용법과 원본 예제: [CHARACTER_STUDIO.md](CHARACTER_STUDIO.md).

## 4. 색상 디더와 픽셀 퍼펙트

색상 디더는 픽셀을 흐리는 보간이 아니다. 지정한 팔레트 중 두 색상만 사용해 셀 단위로
명암을 나눈다. 정확한 팔레트 색은 그대로 두며, 패턴은 물체/월드/화면 좌표에 고정된다.
선형광에서 밝기를 비교하고 가까운 팔레트 색을 시작점으로 혼합 후보를 선택한다.
이는 비용을 제한한 근사 색상 선택이며 모든 팔레트 쌍의 전역 최적화를 의미하지 않는다.

색상과 알파 디더를 동시에 선택하면 `T < alpha`로 남은 셀에 대해 `T / alpha`를 색상 선택에
사용한다. 단순히 같은 `T`를 두 번 사용했을 때 검은 셀만 남는 편향을 피한다.
유한 크기 threshold 패턴이므로 표현할 수 있는 coverage와 명암 단계에는 해상도 한계가 있다.

팔레트 변경은 제작 의도에 따라 opt-in이다. 기존 자유 색상·HDR·coverage 기본 렌더링을
일괄적으로 팔레트나 디더에 가두지 않는다. 투영이 끝난 3D 합성 frame에서는 복구할 수 없는
물체 좌표를 추정하지 않으며 screen 좌표 패턴을 요구한다.

## 5. 게임 자산 출력

프로젝트에 다음을 저장할 수 있다.

```json
{
  "exportSettings": {
    "maxTextureSize": 2048,
    "padding": 2,
    "extrude": 1,
    "trim": true,
    "deduplicate": true
  }
}
```

`extrude`는 `padding` 이하여야 한다. 확장은 저장 rectangle 밖의 여백만 채우므로 원본 픽셀,
trimOffset, pivot, socket 좌표를 변경하지 않는다. 모든 저장 채널이 같은 공간 규칙을 따른다.
이는 고배율 밉맵의 임의 샘플 반경까지 해결하는 기능은 아니다. 정수 배율 픽셀 표시에는
nearest 필터가 기본이며, 소비 엔진의 필터·밉맵 정책은 별도로 맞춰야 한다.

중복 제거는 그림과 HDR이 같은 프레임의 저장 rectangle을 재사용한다. 사건·duration·피벗·
소켓·원본 위치는 프레임별로 유지된다. 클립 시간이 줄어드는 기능이 아니다.
브라우저는 2,048px/16페이지/출력 128 MiB 제한을 유지하며 더 큰 작업은 CLI를 사용한다.

## 검증과 남은 범위

전체 기록은 [검증 결과](validation/production-2026-11-06.json)에 있다.

- Node 전체 811개 검사에서 809개 통과, 2개 실패 원인을 수정했다. 한 건은 테스트의
  extrusion/padding 설정 오류, 다른 한 건은 JSON의 `-0` 정규화와 GPU 예제 축 값의 비트 차이였다.
  관련 22개 재검사에서 모두 통과했으며, 새 GPU 예산 검사 한 건도 이 실행에 포함했다.
- Rust 1.99.1에서 빌드와 7개 계약 검사를 통과했다.
- [실제 WGSL 실행](validation/production-2026-11-06-gpu-tiles.json): 6개 장면,
  18회 compute dispatch, 직접/타일 경로의 1,061,120바이트가 일치했다. 512개 분산 도형에서
  후보 픽셀 검사는 25,395,712회에서 221,696회로 99.127% 감소했다. 타일 분류 경계 검사의
  상한 113,152회는 별도 비용이다. 이는 FPS 개선율이 아니다.
- [native 실행](validation/production-2026-11-06-native.json): 15개 장면, 카탈로그 1개,
  캡처 46개를 CPU 기준 및 반복 실행과 비교해 통과했다.

  환경 제약으로 unavailable이며, PR의 `browser-studio` 작업에서 UI 경로를 검증한다.

원본 크기 [캐릭터 시트](previews/production-character-sync.png)와
[복합 효과 시트](previews/production-charged-impact.png)를 실제로 관찰했다.
캐릭터 시트에서는 12개 시점의 몸체·장비 셀이 일치하고 장비가 부착 위치를 유지했다.
복합 효과 예제는 잠정 검수 상태다. 기존 번개 원본이 0.32초 사건 표시보다 먼저 접점까지
연결되어 있어 "그 시점에 처음 도착한다"는 미술 의도를 검증하지 못했다. 생성된 정상 속도
영상의 재생 관찰은 아직 기록하지 않았고, 정지 시트·자동 테스트를 미술 승인으로 계산하지 않는다.

추가로 확장할 가치가 있는 영역은 물리 GPU별 타일 크기·밀도 자동 선택, 실제 게임 엔진 어댑터,
노드 그래프와 복합 시퀀스의 독립 layer compositing, Aseprite 앱 실사용 왕복, 장르별 원화·
키포즈 팩이다. 현재 구현한 기능과 이 후속 범위를 혼동하지 않는다. 특히 카탈로그 전체의
화려함·미술 품질을 동일한 파티클 수나 발광 값으로 자동 보증할 수 없다.
