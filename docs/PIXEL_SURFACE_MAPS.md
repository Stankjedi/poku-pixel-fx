# 네이티브 높이 기반 음영과 표면 맵

픽셀 표면에 명시한 높이가 있으면 홈과 돌출부가 주변 빛을 가리는 정도,
그리고 솟은 부분이 다른 부분에 드리우는 그림자를 따로 계산할 수 있다.
`pixel-surface-maps`는 이 정보를 네이티브 픽셀 크기로 베이크하고,
노멀·높이·주변광 차폐·방향광 그림자 맵을 만든다.

색상이나 밝기를 보고 높이를 추정하지 않는다. 입력은 직접 작성한 높이와
`createPixelMaterial2D`가 생성한 요철/가장자리 높이이다. 기존 5종 재질과
모든 기존 이펙트의 기본 출력은 그대로이며, 새 재질 음영은 직접 켜서 사용한다.

## 1. 재질에 그림자와 주변광 차폐 추가

```ts
import { createPixelMaterial2D } from 'poku-pixel-fx/core/pixel-material';

const material = createPixelMaterial2D({
  kind: 'stone',
  seed: 41,
  light: [-.8, -.4, .7],
  ambient: .22,
  ambientOcclusion: .65,
  occlusionRadius: 8,
  castShadow: 1,
  shadowDistance: 32,
});

const result = material.shade(source, {
  height: authoredHeight,
  selection: materialRegion,
  protectedMask: handPaintedAccents,
});
```

| 옵션 | 의미 | 기본값 | 범위 |
| --- | --- | --- | --- |
| `ambientOcclusion` | 높이가 주변광을 가리는 효과의 강도 | `0` | `0..1` |
| `occlusionRadius` | 주변 높이를 조사하는 거리 | `8` | 정수 `1..32`셀 |
| `castShadow` | 방향광의 차폐 강도 | `0` | `0..1` |
| `shadowDistance` | 방향광을 따라 조사하는 평면 거리 | `32` | 정수 `1..128`셀 |

두 강도가 모두 0이면 추가 광선 계산을 하지 않는다. 기존 명암 계산을 그대로
실행하며 출력 색·알파·높이·법선은 변하지 않는다. 프로젝트에 정규화해 저장한
설정에는 이 기본값도 함께 기록된다.

주변광 차폐는 주변 밝기 항을 줄이고, 방향광 그림자는 직접광과 반사를 줄인다.
결과 색상은 계속 지정한 팔레트 안에서만 선택한다. 블러, 프레임마다 바뀌는
노이즈, 반투명 가장자리 보정은 추가하지 않는다.

선택 영역과 보호 마스크는 **쓰기 범위**이다. 보호한 픽셀과 미선택 픽셀의
색·알파·기존 재질 채널은 그대로 유지하면서, 이들 위치에 명시한 높이는 주변
픽셀에 대한 차폐 계산에 참여한다. 영역을 선택했다고 가짜 모서리나 빈 구멍이
생기지 않는다. 입력 sprite의 알파가 0이거나 실루엣 마스크가 0인 위치는
차폐 계산에서 제외한다.

## 2. 높이만으로 가시성 계산

```ts
import { bakePixelSurfaceLighting2D } from 'poku-pixel-fx/core/pixel-surface-maps';

const visibility = bakePixelSurfaceLighting2D(width, height, authoredHeight, {
  mask: silhouette,
  light: [1, 0, 1],
  ambientOcclusion: 1,
  occlusionRadius: 8,
  castShadow: 1,
  shadowDistance: 32,
  bias: .02,
});

// Float32Array, 크기는 width * height.
// 1 = 빛이 보임, 0 = 완전히 가림.
visibility.occlusion;
visibility.shadow;
```

재질 옵션과 달리 **독립 맵 베이크**의 두 강도 기본값은 모두 1이다.
`castShadow: 0` 또는 `ambientOcclusion: 0`을 지정하면 해당 계산은 생략하고
모든 셀에 1을 반환한다. 숨겨진 셀도 가시성 1로 남지만, PNG 맵에서는 투명하게
출력되어 실제 물체 표면으로 나타나지 않는다.

좌표는 +x가 오른쪽, +y가 아래쪽, +z가 관찰자 방향이다. `light`는 표면에서
광원을 향하는 벡터이다. 예를 들어 `[1, 0, 1]`은 오른쪽 위의 광원이며,
높은 벽은 왼쪽 바닥에 그림자를 만든다. 벡터를 같은 양수로 배율 변경해도
방향과 그림자는 변하지 않는다.

`bias`는 자기 표면을 잘못 가리는 것을 줄이는 네이티브 높이 간격이며
기본값은 `0.02`, 범위는 `0..16`이다. 정확한 정수 높이 모형을 검증할 때는
0을 사용할 수 있다. 큰 값을 쓰면 낮은 요철의 그림자까지 사라질 수 있다.

### 계산 모델

주변광은 16방향의 높이 지평선을 조사한다. 이웃이 현재 셀의 접평면보다
얼마나 올라오는지로 가림을 계산하므로, 일정하게 기울어진 평면 자체를
오목한 홈으로 오해하지 않는다. 경계나 구멍에서는 존재하는 이웃으로만
접평면을 계산한다. 캔버스 밖은 차폐물이 아니다.

방향광은 셀 격자 경계들을 순서대로 통과한다. 셀 중심만 띄엄띄엄 조사하지
않으므로, 대각선 광선도 한 픽셀 두께의 돌출부를 건너뛰지 않는다.
정확히 모서리만 스치는 옆 셀을 가짜 차폐물로 넣지 않는다.
연속적인 높이 기울기를 셀 안에서 재구성하므로, 완만하게 기울어진 평면이
픽셀 단위의 계단 그림자를 만들지 않는다. 기울기를 주변 높이 차이로
제한해 극점이나 급격한 절벽에서는 지나친 보간을 피한다. 높이 표면
아래는 채워진 것으로 해석한다.

이 기능은 고정 범위의 **높이 필드 근사**이다. 오버행, 여러 층이 겹친 구조,
색이 섞이는 반사광, 굴절이나 실제 메시의 전역 조명을 계산하지 않는다.
부분 알파가 있는 유효 셀은 기하학적으로 하나의 고체 표면으로 취급한다.
출력 알파는 보존하지만 투명 재질의 광학적 투과는 시뮬레이션하지 않는다.

## 3. 엔진용 맵 내보내기

```ts
import { exportPixelSurfaceMaps2D } from 'poku-pixel-fx/core/pixel-surface-maps';

const maps = exportPixelSurfaceMaps2D(result, {
  normalConvention: 'opengl',
  heightRange: [0, 24],
  lighting: {
    light: [-.8, -.4, .7],
    ambientOcclusion: 1,
    occlusionRadius: 8,
    castShadow: 1,
    shadowDistance: 32,
  },
});

// 각 항목은 w, h, pixels: Uint32Array, mask를 가진 네이티브 sprite이다.
maps.normal;
maps.height;
maps.occlusion;
maps.shadow;

// 가시성을 8비트 PNG로 양자화하지 않고 재사용할 수도 있다.
maps.lighting.occlusion;
maps.lighting.shadow;
maps.heightRange;
maps.normalConvention;
```

입력에는 크기가 일치하는 `channels.height`와 `channels.normal`이 필요하다.
PNG만 가져온 상태에서 높이와 법선이 없으면 명시적으로 오류를 반환한다.
원화의 밝은 눈이나 어두운 문양을 임의의 돌출부/홈으로 만들지 않는다.

| 출력 | 인코딩 |
| --- | --- |
| 법선 | 정규화한 XYZ를 RGB의 `0..255`에 저장. 평평한 표면은 `(128,128,255)` |
| 높이 | `heightRange[0]`이 검정, `[1]`이 흰색. 범위 밖은 양 끝값으로 제한 |
| 주변광 차폐 | 흰색이 열린 곳, 검정이 완전히 가린 곳 |
| 방향광 그림자 | 흰색이 직접광을 받는 곳, 검정이 막힌 곳 |

모든 맵은 원본의 유효 알파와 실루엣을 따른다. 부분 알파를 가진 셀도
같은 알파를 유지하며, 마스크 밖의 숨겨진 원본 RGB는 맵에 나타나지 않는다.
각 맵은 독립적인 픽셀/마스크 버퍼를 가진다. 원본 sprite나 재질 채널을
수정하지 않는다.

**법선의 Y 방향을 엔진 설정과 맞춰야 한다.** 내부 법선은 y-down 좌표이다.
`opengl`은 녹색 채널을 뒤집어 tangent y-up으로 인코딩하고,
`directx`는 y-down을 그대로 인코딩한다. 두 형식의 빨강·파랑은 같다.
해당 이름은 파일 인코딩 관례이며 사용하는 그래픽 API를 자동 감지하지 않는다.
법선·높이·차폐 맵을 색 보정하는 일반 사진처럼 처리하면 값이 변한다.
엔진에서는 데이터 텍스처로 읽고, 네이티브 픽셀을 유지하려면 필터링도
의도에 맞게 설정한다.

`heightRange`를 생략하면 실루엣 안쪽 높이의 최소/최대를 사용한다.
단일 표면을 확인하기에는 편하지만 애니메이션에서 프레임별로 범위를
다르게 정하면 같은 회색이 서로 다른 높이를 뜻하게 된다. 여러 프레임이나
서로 연결되는 타일은 **동일한 범위**를 명시한다. 높이가 모두 같거나
유효한 표면이 없는 경우 높이 이미지는 검정이고, `heightRange`로 실제
상수값을 구분할 수 있다.

PNG 인코더에는 `pixels`에서 추출한 RGBA 바이트를 직접 전달한다.
이 저장소 브라우저 도구의 `gallery/png.ts`에는 `encodeRGBAPNG`가 있다.
Canvas의 프리멀티플라이/역변환을 거치면 부분 알파에서 법선의 RGB 값이
반올림될 수 있으므로, 정확한 데이터 맵에는 직접 인코딩 경로를 사용한다.

## 4. 반복 편집과 성능 범위

방향·시드·높이가 같으면 결과는 동일하다. 실행 시간이나 프레임 번호를
읽지 않는다. GPU용 데이터로 내보낼 수 있지만 베이크 자체는 CPU 작성
작업이다. 애니메이션 매 표시 프레임마다 재계산하기보다 높이 또는
광원 설정이 바뀔 때 베이크하고 결과를 캐시한다.

메모리는 셀 수에 비례한다. 광선 계산량은 대략 유효 셀 수에
`16 × 주변광 반경 + 방향광의 격자 통과 수`를 곱한 값에 비례한다.
반경·거리 상한과 함께 한 번의 베이크에서 예상 방문 셀 수를
**134,217,728회 이하**로 제한한다. 이 범위를 넘는 명시적 요청은
버퍼를 수정하지 않고 오류를 반환한다. 반경이나 거리를 줄여 다시
베이크할 수 있다. 이는 실제 GPU 성능 측정값이 아니다.

잘라낸 조각의 주변 차폐 정보가 필요하면 전체 높이/실루엣에서 먼저
베이크한 뒤 자른다. 별도 타일로 계산할 때는 반경·그림자 거리만큼
이웃 기하학 정보를 포함한 패딩 영역이 필요하다. 새 캔버스 경계 바깥에
원래 있던 차폐물을 자동 복구하지 않는다.

자주 갱신되는 법선·높이 미리보기만 필요한 경우에는 기존 채널을
직접 표시하거나 `lighting: {ambientOcclusion: 0, castShadow: 0}`을
지정해 불필요한 가시성 계산을 생략한다.

## 검증 범위

`tests/pixel-surface-maps.test.mjs`는 일정 경사 평면, 독립적으로 계산한
절벽의 그림자 방향과 길이, 대각선 한 셀 차폐, 구멍, 주변광 반경/강도,
높이 이동 불변성, 부분 알파, 보호 영역, 팔레트 보존, 법선 Y 인코딩,
고정 높이 범위와 작업량 제한을 검사한다. 미술적 완성도는 수치 검사의
대상이 아니며 네이티브 출력에서 별도로 확인해야 한다.
