# Fire transport and convection

`flowMotion(initial, age, phases)` is a pure, seekable motion sampler exported from `core/index`
and the package root. Each phase applies constant acceleration and exact linear drag, then hands both
position and velocity to the next phase. The sample at a phase boundary is continuous, even when the
forces change. It uses the same stable integrator as the shared particle systems, including tiny or
zero drag. This is an authored transport model, not a fluid solver.

```ts
const state = flowMotion({ x: 0, y: -12, vx: 14, vy: -32 }, age, [
  { duration: 0.5, ax: 10, ay: -105, drag: 1.6, dragY: 1.8 }, // hot, buoyant flame
  { duration: Infinity, ax: 4, ay: -18, drag: 0.65, dragY: 1 }, // cooling smoke
]);
```

- Coordinates and acceleration use the existing pixel/second units; negative y rises.
- Only the last phase may have infinite duration. An all-finite timeline clamps samples at its end.
- Sampling consumes no RNG and does not mutate the initial state or phases.
- The same helper can model a directed jet becoming drifting mist, or fast debris becoming residue.
- Use a separate coverage envelope and color ramp. Motion continuity alone does not prevent visual pops.

## Effects

`fire/convection-plume` is a three-second loop with a coal-rooted, forked flame. Travelling folds move
upward through its layered silhouette; hot detached puffs cool into expanding translucent soot;
sparse embers inherit upward drift. White is restricted to a small hot core. Controls include `wind`
(-10..24, art-directed clamp), `height` (28..62), smoke and flame palettes, and seed. Wind changes both
lean and transport; it is not a blanket rotation of the effect.

`fire/flamethrower` now freezes each curl's emission point at birth and carries its tangent velocity
into smoke. Cooling no longer replaces that velocity abruptly with a fixed direction. Smoke drag
keeps the existing 184×104 canvas. The default is `flowStyle: "continuous"`; use
`flowStyle: "classic"` to retain the previous color and light buffers. The dimensions, anchor,
loop duration, seed behavior, and all unrelated fire effects are unchanged.

## Review and regression

Three visual passes were rendered and inspected:

1. Initial narrow contours looked like parallel blades. The next pass widened the rooted silhouette,
   added travelling folds, varied side-tongue heights, and trimmed empty canvas space.
2. The fuller flame read clearly, but generic polygons took about 5.4 ms/frame in the checker. Caching
   local row spans preserved the contour while keeping inverse rasterization correct under rotation.
3. Final default/seed checks passed without bounds or timing warnings. A warmed-up local measurement
   of the plume was about 0.57 ms median / 1.04 ms p95; timings depend on machine and load. The initial
   flamethrower smoke overshot its old top edge, so cooling drag was refined without moving the anchor.

`tests/flow-quality.test.mjs` verifies position/velocity continuity, analytic phase composition,
small-drag stability, seek purity, rejected invalid inputs, exact loop endpoints, classic flame-jet
buffer hashes, palette/seed/transform variants, smoke translucency, and color bounds across complete
loops with several seeds. GIFs and transparent PNG/JSON sprite sheets are generated by the normal
render tool. Artistic review remains necessary; numerical continuity is not a visual-quality guarantee.
