# 스프라이트시트를 편집 가능한 애니메이션으로 가져오기

시트에 모아 둔 캐릭터 포즈·배경 타일·이펙트 프레임을 원본 픽셀 크기로 잘라
Pixel Art Lab의 프레임 문서로 가져오는 도구다. 시트 전체를 한 장의 정지 그림으로
다시 그릴 필요 없이 각 프레임의 픽셀·팔레트·레이어를 독립적으로 수정할 수 있다.

입력은 두 가지다.

| 입력 | 복원하는 내용 |
| --- | --- |
| POKU가 내보낸 시트 PNG + `poku-pixel-art-atlas/v1` JSON | 원래 프레임 순서·ID·이름·각 프레임 시간·재생 방향·반복 설정 |
| 같은 크기 셀을 배치한 일반 PNG | 지정한 셀 크기·여백·간격·순회 방향·시작 위치·개수에 따른 프레임 |

PNG의 straight RGBA를 직접 복사한다. 완전히 투명한 픽셀의 숨은 RGB와 알파 1 같은
낮은 알파도 보존하며, 리샘플링이나 Canvas 합성으로 색을 다시 계산하지 않는다.
각 프레임은 기존 `poku-pixel-art/v2` 문서이고 전체 애니메이션은 기존 v3 형식을 사용한다.
기존 프로젝트 형식이나 이펙트의 기본 동작은 바꾸지 않는다.

## 내보낸 POKU 시트 다시 열기

```ts
import {
  importPixelArtAnimationSheet2D,
  serializePixelArtAnimation2D,
} from 'poku-pixel-fx/authoring';

// nativeSheet: { w, h, pixels: Uint32Array, mask: { w, h, data: Uint8Array } }
// PNG를 정확한 네이티브 RGBA로 디코딩한 결과다.
const animation = importPixelArtAnimationSheet2D(nativeSheet, atlasManifest);
const editableProject = serializePixelArtAnimation2D(animation);
```

프레임 사각형이 실제 시트 안에 있고 크기가 서로 같은지 먼저 확인한다.
원래 시트에서 여러 프레임이 같은 사각형을 참조해도 각 프레임은 독립 배열을 가진다.
한 프레임을 수정해 다른 프레임이나 입력 시트가 함께 변하지 않는다.

JSON에 기록한 `sequence`, `startsMs`, 전체 `durationMs`는 원본 프레임 시간과 재생 방향으로
다시 계산한 값과 일치해야 한다. 모순된 시간을 임의로 선택하지 않고 가져오기를 거절한다.
정방향·역방향·왕복은 기존 타임라인 규약을 그대로 사용한다. 예를 들어 3프레임의 왕복은
`0 → 1 → 2 → 1`이며, JSON을 읽었다고 왕복 구간을 실제 프레임으로 중복 생성하지 않는다.

추가 `image` 필드는 파일 이름 정보일 뿐이다. 가져오기 API가 그 주소를 자동으로 요청하거나
외부 코드를 실행하지 않는다. 호출자가 이미 디코딩한 시트와 읽은 JSON만 사용한다.
현재 선택 프레임은 시트에 저장하지 않으므로 가져온 프로젝트에서는 첫 원본 프레임을 선택한다.

## 일반 시트의 격자 자르기

```ts
import { slicePixelArtAnimationSheet2D } from 'poku-pixel-fx/authoring';

const animation = slicePixelArtAnimationSheet2D(nativeSheet, {
  name: '도시 탐험가 · 걷기',
  frameWidth: 64,
  frameHeight: 96,
  margin: [2, 2],
  gap: [4, 4],
  order: 'row-major',
  start: 0,
  count: 8,
  durationMs: 1000 / 24,
  direction: 'forward',
  loop: true,
  skipEmpty: false,
});
```

| 옵션 | 의미 |
| --- | --- |
| `frameWidth`, `frameHeight` | 각 프레임의 실제 픽셀 너비·높이. 자동 축소하지 않는다. |
| `margin` | 양쪽 바깥 여백. 숫자 하나는 두 축에 적용하고 `[x,y]`는 좌우·상하 여백을 각각 정한다. 기본 0. |
| `gap` | 인접 셀 사이 빈 간격. 숫자 하나 또는 `[x,y]`. 기본 0. |
| `order` | `row-major`: 왼쪽→오른쪽으로 한 행씩. `column-major`: 위→아래로 한 열씩. |
| `start` | 선택한 순회 방식에서 0부터 세는 첫 원본 셀 번호. 기본 0. |
| `count` | 검사할 원본 셀 수. 생략하면 시작 셀 이후 전체를 사용한다. |
| `skipEmpty` | 보이는 픽셀이 없는 셀의 명시적 제외. 기본 `false`. |
| `durationMs` | 각 가져온 프레임의 시간. 소수 밀리초도 유지한다. 기본 100. |
| `direction`, `loop` | 기존 애니메이션의 방향·반복 설정. 기본 정방향·반복. |

셀은 실제 사각형 전체가 시트 안에 들어가는 경우에만 나열한다. 오른쪽·아래쪽에 남은
불완전한 띠는 프레임으로 만들지 않는다. 시트에 패딩이 있다면 `margin`과 `gap`을 맞추어
그림 경계가 잘리지 않게 한다. 원본 이미지를 보간해 잘못 맞는 격자를 숨기지 않는다.

`start`와 `count`를 먼저 적용한 뒤 선택한 범위에서 빈 셀을 제외한다.
예를 들어 원본 2·3·4번째 셀 중 3번째가 비어 있다면, `skipEmpty`를 켰을 때 남는 ID는
`frame-2`, `frame-4`다. 뒤 프레임을 다시 번호 매기지 않아 원래 시트 위치를 추적할 수 있다.

완전히 투명한 프레임은 잠깐 사라지는 모션이나 프레임 간 시간을 표현할 수 있다.
그래서 기본값에서는 모두 보존한다. `skipEmpty:true`는 실루엣이 있고 알파가 0보다 큰 픽셀이
하나도 없는 프레임을 제외한다. 그 프레임에 숨은 RGB나 표면 데이터가 있어도 명시적으로
제외된다. 모든 셀이 비면 빈 애니메이션을 만들지 않고 오류를 반환한다.

## 표면 채널과 편집 데이터

API 입력에 시트 전체 크기의 `channels`를 함께 제공하면 `material`, `height`, `normal`도
색과 동일한 좌표로 복사한다. 잘라낸 경계를 새로운 물체 경계로 간주해 법선을 다시 계산하지
않으며, 높이와 음수 값·소수 값도 그대로 유지한다. 입력 실루엣의 0은 비점유, 그 외 값은
점유로 해석하고 v2의 이진 마스크로 저장한다.

일반 PNG에는 편집 레이어나 원래 독립 실루엣·높이·법선이 들어 있지 않다.
시트 PNG만 가져오면 시각적 RGBA와 그 알파로 만든 마스크를 얻고, 레이어는 빈 상태에서
새로 편집한다. 원래 재질·곡선·보호 영역·조각 작업까지 이어서 수정하려면 v3 프로젝트를 연다.
PNG 시트에 없는 채널을 색에서 추측해 복원하지 않는다.

## 크기 제한과 실패 시 동작

모든 사각형·이름·시간·색상/마스크/표면 배열의 형태를 검사하고 다음 예산을 확인한 뒤
프레임 배열을 복사한다.

- 시트: 가로·세로 최대 16,384픽셀, 총 16,777,216셀.
- 프레임: 기존 문서의 최대 1,048,576셀, 애니메이션 최대 256프레임.
- 합산: 8,388,608 네이티브 셀, 16,777,216 저장 숫자, 기존 렌더 예산.
- 저장: 최종 JSON의 실제 UTF-8 크기 64 MiB 이하.

색·마스크만 있으면 프레임당 셀 수의 2배, 표면 맵까지 있으면 7배의 숫자를 저장한다.
셀 개수가 허용 범위여도 긴 RGBA 숫자와 실수 때문에 JSON이 너무 커질 수 있다.
가져오기는 원본에서 실제 숫자의 직렬화 길이까지 계산해 저장할 수 없는 프로젝트를
대형 프레임 배열로 먼저 만들지 않는다. 이 계산은 결과 전체 JSON을 임시로 생성하지 않는다.

API는 입력을 변경하지 않는 순수 함수다. 잘못된 입력은 부분적인 애니메이션을 돌려주지 않는다.
편집기는 완성된 후보의 렌더·히스토리 준비가 성공한 뒤에 현재 문서와 교체해야 한다.

## 검증

`tests/pixel-art-sheet.test.mjs`는 다음 제작 계약을 검사한다.

- 기존 시트 내보내기 → 가져오기 → 저장/재열기 → 다시 내보내기의 RGBA·시간 일치.
- 역방향·왕복·서로 다른 프레임 시간, 투명한 유지 프레임과 숨은 RGB.
- 행/열 순회, 서로 다른 여백과 간격, 시작/개수, 명시적 빈 셀 제외.
- 겹친 사각형의 프레임 독립성, 원본 보존, 색·실루엣·표면 채널의 좌표 일치.
- 전체 애니메이션 실행 취소, 잘못된 사각형·시간·입력 배열과 용량 초과 거절.

```sh
npm run build
node --test tests/pixel-art-sheet.test.mjs
```

이 검사는 가져온 데이터와 제작 흐름의 정확성을 확인한다. 캐릭터 포즈나 프레임 사이의
움직임을 자동으로 보완하거나 미술적 완성도를 판정하는 기능은 아니다.
