# 작업 팔레트 저장과 브라우저 복구

Pixel Art Lab은 작업 팔레트를 프로젝트에 함께 저장하고, 완료한 편집을 이 브라우저에 자동으로 기록합니다.
새로고침한 뒤 상단의 **선택한 작업 복구**로 이어서 작업할 수 있습니다.

## 작업 팔레트가 원화와 함께 남습니다

그림에서 추출하거나 직접 만든 작업 팔레트는 적용 버튼을 누르지 않아도 프로젝트 파일에 남습니다.
색상 순서와 원래 packed RGBA를 보존하며, 이 정보만으로 그림 색을 바꾸거나 팔레트 조정 레이어를 추가하지 않습니다.
기존 조정 레이어에서 불러온 최대 256색 팔레트도 잘라내지 않고 보존합니다.
팔레트를 실제 원화에 적용하려면 기존 **팔레트 조정 레이어 추가** 또는 **작업 팔레트를 모든 프레임에 적용**을 사용하세요.

v2 원화는 선택적인 `workingPalette`를, v3 애니메이션은 전체 프레임이 공유하는 `workingPalette`를 사용합니다.
기존 문서처럼 이 필드가 없어도 열립니다. 각 cel의 문서에 있던 팔레트도 별도로 보존하지만,
작업실에서 프레임을 바꾸는 동안에는 애니메이션의 공통 작업 팔레트를 유지합니다.
현재 모습 굽기, 프로젝트 저장·재열기와 문서 히스토리는 이 메타데이터를 보존합니다.

## 자동 저장과 명시적 복구

**이 브라우저에 자동 저장**을 켜면 편집이 멈춘 뒤 약 0.9초 후 복구본을 기록합니다.
완성된 그리기 획, 적용한 곡선·높이·조명 레이어, 프레임 문서와 시간, 선택·보호, 작업 팔레트가 대상입니다.
저장 직후에는 상단 상태가 **자동 저장 완료**로 바뀝니다.

- **복구본 지금 저장:** 현재 유효한 편집을 마무리하고 복구본을 기록합니다. 자동 저장을 꺼도 사용할 수 있습니다.
- **선택한 작업 복구:** 저장된 목록에서 원화를 선택해 엽니다. 현재 작업부터 별도 복구본에 보관합니다.
- **선택한 복구본 삭제:** 선택한 저장본을 정리합니다. 현재 화면의 원화는 유지합니다.

이전 복구본이 있어도 시작 화면을 자동으로 바꾸지 않습니다. 목록에서 이름·프레임 수·저장 시간을 확인하고 직접 선택합니다.
여러 탭을 사용하거나 탭을 복제해도 각 작업은 서로 다른 복구본에 기록합니다.
복구한 직후 다시 새로고침하면 선택했던 복구 원본이 우선 표시되고, 복구 이전 작업도 목록에 남습니다.

열린 경로 초안이나 아직 끝나지 않은 포인터 획은 배경 타이머가 임의로 확정하지 않습니다.
**복구본 지금 저장**, 프로젝트 저장, Enter/적용 등으로 완료한 뒤 화면의 저장 상태를 확인하세요.
재질 미리보기는 기존 프로젝트 저장과 같이 현재 설정으로 저장될 수 있습니다.
실행 취소의 모든 과거 스냅샷을 브라우저 복구본에 보관하는 방식은 아닙니다.

## 저장 실패와 편집 상태

복구본 본문과 목록 정보는 하나의 IndexedDB 트랜잭션에 기록합니다.
공간 부족, 브라우저 저장 권한 제한, 중간 쓰기 실패에서는 기존 성공한 저장본을 유지하고 상태를 표시합니다.
자동 저장을 끄면 이미 시작한 쓰기는 마칠 수 있지만, 그 뒤의 편집을 계속 따라가며 저장하지 않습니다.
명시적 저장은 내용이 같아도 실제 기록을 수행하므로 다른 탭이 해당 복구본을 삭제한 뒤에도 다시 저장할 수 있습니다.

저장·삭제·복구는 순서대로 처리합니다. 복구하는 동안 잠시 편집 입력을 막고 현재 상태를 먼저 보관하므로,
파일을 읽거나 다른 복구본을 저장하는 사이에 새 획이 사라지지 않습니다.
불러올 문서는 검증하고 렌더한 다음 화면에 반영합니다. 잘못된 복구본은 현재 원화를 대체하지 않습니다.

브라우저 데이터 삭제·시크릿 창 종료·저장 공간 정책의 영향을 받을 수 있습니다.
기기 사이 이동과 장기 보관에는 **프로젝트 JSON 저장**을 사용하세요.
복구 데이터는 해당 사이트의 브라우저 저장 공간에만 기록하며, 별도 서버 업로드를 추가하지 않습니다.

## 검증

`tests/pixel-workspace-state.test.mjs`는 팔레트 메타데이터가 원화 출력에 영향을 주지 않는지,
저장·굽기·히스토리·독립 cel에서 보존되는지, 잘못된 값이 입력을 바꾸지 않고 거부되는지 검사합니다.

`tools/pixel-art-recovery-browser-harness.mjs`는 실제 파일 입력, IndexedDB, 새로고침, 복구 버튼과 프로젝트 출력을 사용합니다.
두 번째 저장 요청에 주입한 실패의 트랜잭션 원자성, 외부 저장 연결의 삭제 후 재저장,
저장 중 자동 저장을 끈 뒤의 편집, 잘못된 복구본, 여러 cel과 공유 팔레트, 390px 화면을 확인합니다.
이 검사는 실제 사용자의 모든 브라우저 저장 정책이나 종료 시점을 보장하는 시험은 아닙니다.
