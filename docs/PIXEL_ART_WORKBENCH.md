# Pixel Art Lab — 픽셀 제작 작업실

정밀 선택·변형, 필압·명암 브러시, 반복 재질·재조명과 프레임 애니메이션은
[정밀 편집과 애니메이션 제작](PIXEL_ART_PRO.md)에 이어서 설명합니다. 같은 작업실에서 사용할 수 있습니다.

기존의 곡선·재질 작성에 **직접 그리기, 편집 레이어, 지각 기반 팔레트, 높이 기반 음영과 표면 맵**을 연결했다.
원본 크기에서 윤곽과 색 덩어리를 다듬은 뒤 게임에서 사용할 이미지와 재질 정보를 내보내는 작업 흐름이다.
기존 이펙트 카탈로그와 기본 렌더링은 유지한다.

## 실행

```sh
npm ci
npm run build
npm run gallery
```

`http://127.0.0.1:8080/gallery/pixel-art-lab.html`을 연다. 기존 Pixel Art Lab과 같은 주소다.

## 제작 흐름

1. 기존 예제나 PNG·프로젝트를 열거나 **새 캔버스에서 직접 그리기**로 시작한다.
2. 왼쪽에서 재질을 적용할 영역을 고르고, 얼굴·자수·문양처럼 유지할 부분을 보호한다.
3. 오른쪽에서 재질의 큰 명암을 확인하고 **선택 영역에 재질 적용**을 누른다.
4. 그리기 도구를 골라 오른쪽 캔버스에서 윤곽·금속 가장자리·실밥·하이라이트 등을 직접 수정한다.
5. 색상 설계에서 팔레트를 추출하거나 그림자·중간색·밝은 면으로 명암 팔레트를 만든다.
6. 필요한 경우 팔레트 조정 레이어를 더하고, 레이어의 순서와 표시를 비교한다.
7. 원본 크기 PNG, 편집 프로젝트, Normal·Height·AO·Shadow PNG를 저장한다.

단순히 색 수를 늘리거나 표면에 노이즈를 뿌려 완성도를 평가하지 않는다. 곡선의 계단 간격,
큰 명암 덩어리, 재질의 방향성과 필요한 한 픽셀 강조를 각각 조절할 수 있도록 구성했다.

## 그리기와 선택

| 기능 | 동작 |
| --- | --- |
| 연필 | 정수 셀을 잇는 연속 스트로크. 빠르게 이동하는 포인터 사이도 채운다. |
| 픽셀 퍼펙트 | 1px 스트로크의 불필요한 직각 중간 픽셀을 현재 스트로크 안에서 제거한다. |
| 지우개 | 선택한 그림 레이어에 투명한 셀 교체를 기록한다. 아래 원본까지 뚫리는 명시적 지움이다. |
| 직선·사각형·타원 | 실제 셀에 도형을 채우거나 내부 두께를 가진 윤곽을 만든다. |
| 색 채우기 | 현재 보이는 합성 결과에서 연결된 유사색을 찾고, 활성 그림 레이어에 기록한다. |
| 색 추출 | 합성 결과의 실제 RGB를 그리기 색으로 가져온다. |
| 좌우·상하 대칭 | 캔버스 중앙을 기준으로 붓 전체 모양을 반사한다. 짝수·홀수 크기를 모두 처리한다. |
| 투명도 잠금 | 활성 그림 레이어의 원본 알파를 유지한다. 새 그림 레이어에서는 현재 합성 결과를 기준으로 한다. |
| 선택 내부만 | 체크하면 그리기·팔레트 조정이 선택 영역 안으로 제한된다. |
| 디테일 보호 | 재질·그리기·팔레트 조정에서 지정한 픽셀을 유지한다. |
| 선택 확장·축소 | 유클리드 거리로 1px 확장·축소한다. 대각선이 사각형처럼 부풀지 않는다. |
| 격자·타일 확인 | 화면 오버레이와 3×3 반복 미리보기. 출력 PNG에는 포함하지 않는다. |

단축키는 `B` 연필, `E` 지우개, `L` 직선, `R` 사각형, `O` 타원, `G` 채우기, `I` 색 추출이다.
`Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z`로 실행 취소·다시 실행하고 `Ctrl/Cmd+S`로 프로젝트를 저장한다.
입력 필드에 글자를 쓰는 동안에는 그리기 단축키가 개입하지 않는다.
진행 중인 스트로크에서 저장·실행 취소를 누르면 먼저 그 스트로크를 확정하므로 화면과 저장 결과가 어긋나지 않는다.

그리기는 원본 셀을 직접 바꾸는 기능이다. 픽셀 퍼펙트 모드는 곡선의 표현 의도를 자동 판단하지 않는다.
작은 직각 장식이 필요하면 이 기능을 끄고 그린다. 자동 대칭도 필요한 부분에서만 사용한다.

## 편집 가능한 레이어

문서의 레이어는 아래에서 위로 적용한다. 목록에서는 위쪽 행이 최종 출력에 가까운 레이어다.

- **재질:** 시드, 조명, 재질, 높이, 선택과 보호 영역을 저장한다. `설정`으로 기존 레이어를 다시 편집한다.
- **그림:** 수정한 셀과 정확한 RGBA만 기록한다. 연속 스트로크를 같은 그림 레이어에 쌓을 수 있다.
- **색상:** 팔레트와 디더 좌표, 선택과 보호 영역을 기록하는 조정 레이어다.

이름 변경, 표시 전환, 위·아래 순서 이동, 편집 잠금, 삭제를 지원한다. 잠긴/숨겨진 그림 레이어에
그리면 새 레이어를 몰래 만들지 않고 선택 상태를 안내한다. 재질 레이어를 선택한 상태에서 그리면
맨 위에 그림 레이어를 만든다. 아래쪽 그림 레이어는 그 위의 재질·색상 레이어를 거쳐 보인다.

**현재 모습 굽기**는 표시된 결과를 새로운 원본으로 만든다. 색상·알파·실루엣과 재질의 높이·법선을
함께 보존하며 실행 취소할 수 있다. 숨긴 레이어는 구운 결과에 포함하지 않는다.

최대 레이어 수는 32개이며 해상도에 따라 총 셀 예산으로 줄어든다. 대기 중인 재질 미리보기도
추가 레이어가 필요한 동작의 용량 계산에 포함한다. 기존 그림 레이어의 추가 스트로크는 레이어 수를 늘리지 않는다.
실행 취소는 최대 64단계이며 과거 스냅샷에 32MiB 예산을 둔다. 큰 문서에서는 유지되는 단계 수가 줄어든다.
현재 문서는 이 과거 기록 예산 때문에 삭제되지 않는다.

## 팔레트 설계

색 추출은 보이는 픽셀을 알파 가중치로 모으고 Oklab에서 색상 차이를 비교한다. 투명 영역의 숨은 RGB가
팔레트를 차지하지 않는다. **그리기 색 유지**를 켜면 선택한 색을 그대로 팔레트에 남긴다.
요청한 색 수는 상한이며, 색이 적은 그림에서 존재하지 않는 차이를 강제로 만들어 채우지 않는다.

명암 팔레트는 그림자·중간색·밝은 면을 Oklch에서 연결하고 표시 가능한 색역으로 채도를 줄인다.
단순한 RGB 보간보다 명도와 색상 이동을 분리해서 다루기 위한 도구다.
작업 팔레트 생성과 수정은 적용 전까지 그림을 바꾸지 않는다. **재질 팔레트에 사용**은 재질 미리보기에,
**팔레트 조정 레이어 추가**는 현재 보이는 출력의 색 정리에 각각 사용한다.

디더링은 기본적으로 꺼져 있다. 필요한 경우 4×4 또는 8×8 규칙 패턴을 선택한다. 패턴은 명시한 물체
좌표에 고정되며 프레임마다 새 난수를 만들지 않는다. 기존 팔레트에 정확히 들어 있는 색은 디더로 흔들지 않는다.

[팔레트 API 및 계산 범위](PIXEL_PALETTE.md)

## 높이 기반 조명과 게임용 맵

재질의 **홈과 접촉부 음영**은 높이 지도의 주변 지평선을 검사하는 AO이고,
**높이가 만드는 그림자**는 광원 쪽의 실제 높이와 실루엣을 따라 계산한다.
두 기능의 기본 강도는 0이어서 이전 재질 출력은 바뀌지 않는다.
투명 구멍과 캔버스 바깥은 차폐물이 아니며, 선택 영역의 테두리도 새로운 벽이 되지 않는다.

| 출력 | 규약 |
| --- | --- |
| Normal PNG | 내부 좌표는 +x 오른쪽, +y 아래쪽, +z 관찰자. OpenGL 출력은 녹색 축을 뒤집고 DirectX는 유지한다. |
| Height PNG | 표시된 최소~최대 높이를 8비트로 정규화한다. 정확한 범위는 맵 정보 JSON에 기록한다. |
| AO PNG | 흰색은 열린 표면, 검은색은 차폐된 표면이다. |
| Shadow PNG | 흰색은 직접 빛을 받는 영역, 검은색은 가려진 영역이다. |
| 맵 정보 JSON | 크기, 좌표 규약, 높이 단위와 인코딩을 기록한다. |

AO/Shadow 출력은 강도 1의 원시 가시성 맵이며 현재 화면의 재질 강도를 구워 넣은 최종 색상이 아니다.
표시된 재질의 광원 방향과 조사 반경·거리를 사용한다. 여러 재질에 서로 다른 광원을 준 작품에서는
마지막으로 표시되는 재질의 광원을 단일 맵의 기준으로 삼는다. API에서는 원하는 광원과 높이 범위를 지정할 수 있다.
애니메이션 여러 프레임에 Height PNG를 사용할 때는 API의 `heightRange`를 고정해야 동일한 회색이 동일한 높이를 뜻한다.

이것은 높이 필드에서 베이크하는 CPU 작성 도구다. 복잡한 오버행을 포함한 완전한 3D 레이트레이서나
원화의 의미를 자동 이해하는 생성 모델은 아니다. 형태·주름·능선의 높이는 작성자가 지정한다.
AO 반경과 그림자 거리, 총 조사 예산을 제한하며 유효한 옵션이라도 매우 큰 요청은 명확한 오류로 거절한다.
그 경우 프로젝트를 바꾸기 전에 후보 렌더를 확인하므로 이전 작업과 화면을 유지한다.

## 저장과 호환성

작업실의 저장 형식은 `poku-pixel-art/v2`다. 원본 RGBA·독립 마스크, 재질·그림·팔레트 레이어,
편집 선택과 보호 영역, 작성한 높이, 활성 레이어를 보존한다.
기존 `poku-pixel-art/v1` 프로젝트는 원래 검증기를 거쳐 읽고 동일한 출력으로 확장한다.
라이브러리의 기존 v1 함수와 파일 규약은 유지하며, v2에는 다음 API를 사용한다.

```ts
import {
  createPixelArtDocument2D, renderPixelArtDocument2D,
  serializePixelArtDocument2D, parsePixelArtDocument2D,
} from 'poku-pixel-fx/authoring';

const document = createPixelArtDocument2D(sprite, 'Detailed prop');
document.layers.push({
  kind: 'material', id: 'stone-1', name: 'Stone body',
  material: {kind: 'stone', seed: 41, ambientOcclusion: .65, castShadow: .8},
  height: authoredHeight,
});
document.layers.push({
  kind: 'paint', id: 'inlay-1', name: 'Hand-authored highlight',
  indices: [210, 211], pixels: [0xffb5dff4, 0xffb5dff4],
});
const reopened = parsePixelArtDocument2D(serializePixelArtDocument2D(document));
const output = renderPixelArtDocument2D(reopened);
```

도형·붓·선택의 재사용 API는 [Pixel Brush](PIXEL_BRUSH.md)를 참고한다.

PNG와 맵은 원본 크기의 straight RGBA를 직접 인코딩한다. Canvas PNG 저장에서 발생할 수 있는
낮은 알파의 RGB 반올림을 피한다. 화면의 투명 픽셀 표현은 브라우저 Canvas의 합성 규칙을 따르지만
프로젝트와 내보낸 PNG는 원래 RGBA를 보존한다.
8비트 이하 PNG는 일반·Adam7 인터레이스 모두 전용 디코더로 RGB·알파를 직접 읽는다.
16비트 PNG는 명시적으로 알린 뒤 브라우저에서 변환하며, 잘못된 CRC나 손상된 압축 데이터는 오류로 처리한다.
일반 정지 이미지의 512픽셀 한도와 별도로, 스프라이트시트 가져오기는 명시한 큰 시트 예산을 사용한다.
파일의 색상 프로파일을 변환하지 않고 저장된 수치를 유지한다. [PNG 가져오기 규약](PIXEL_PNG_IMPORT.md)을 참고한다.
화면 확대·격자·선택·타일 보기·진단은 출력에 섞이지 않는다.

## 검증

```sh
npm run build
npm run test:pixel-art
GPU_BROWSER_PATH=/path/to/chromium npm run test:browser:pixel-art
GPU_BROWSER_PATH=/path/to/chromium npm run test:browser:workbench
npm run preview:pixel-workbench
```

자동 검사는 픽셀 연결, 색과 알파, 레이어 순서, 저장 재현, 광원 방향, 브라우저 조작을 확인한다.
미술적 완성도는 원본 크기와 확대 결과를 직접 보고 판단한다.
